Turn 6 · Reconciled with the contract
What changed, and what to hand over
The frames in turns 1–5 are updated in place rather than redrawn, so there is one current version of each screen. Everything below is the mapping Claude Code needs: which element ids each drawn region corresponds to, and the three places the earlier drawings were wrong about the backend.
CORRECTED
32 · Kickoff lock, not a slate deadline
Every picks screen now says each game locks at its own kickoff. The Thursday night game in 1a and 5a carries a KICKED OFF badge, sits at 55% opacity and its six cells no longer respond — that is .game.started with disabled chips. Use gameStarted(game) and let a missing kickoff fail open. The old "Picks locked" screen is gone; submitting now confirms and stays editable.
CORRECTED
33 · Queries is qView, not a query builder
Four dropdowns became three controls: VIEW (qView), PLAYER (qPlayer) and SEASON (seasonPicker). The eight view options are exactly the eight the render code switches on, labelled in plain words: Win % by player, Win % by market, Units by market, NFL vs college, Win % by week, Cumulative units, Best teams, Worst teams. Chart type follows the view — week views draw the line, everything else the bars — so drawBars() keeps its job.
CORRECTED
34 · There is no login
The name and email fields are the identity, so they belong on the page, not behind an avatar. 1a puts nameInput and emailInput as a two-up row under the header; the circle beside the season chip is userBadge and holds btnLogout on tap. Do not design a sign-in flow around a field the backend simply trusts.
35 · Make Picks id map
Week arrows are btnPrevWeek / btnNextWeek, the date is weekLabel and tapping it is btnThisWeek. League chips are sportFilter — a select in the contract, a three-chip row in the design, which is a free change if the JS reads its value. The odds grid is games, each cell a .chip / .chip.selected. The bottom slot bar is picksList.
36 · The rule counters still exist
The five slots are a visual form of the counters, not a replacement: keep ruleFD and ruleOU as the FAV / DOG / OVER / UNDER slots, ruleML as the ML slot (its "invalid odds" state is what dims short prices), ruleNFL and ruleCFB as the league tally line, and ruleMsg as the submit button's label. Same six elements, same text, arranged as slots.
37 · Both slips stay real tables
1b and 5b are drawn as cards and rows, but build them as myPicksTable and boardTable with their data-label cells intact — the phone layout is that same table with the existing card CSS, and the desktop layout is the table shown as a table. That is what keeps this a restyle. The week dropdown in 5c is weekPicker feeding weekTable.
38 · Say when it last graded
Grading runs every six hours, so a result can be that stale and the page never admits it. GRADED 3H AGO now sits under the Queries controls; put the same line on Scoreboard and My Picks, derived from the newest graded ts in the payload. When the season selector is off the newest season, .seasonBar.stale gets an amber outline.
39 · Nothing here needs a new endpoint
One exception: the team records beside each team in the odds grid (8-4, 6-6) are not in the feed. Drop them and the layout is unaffected — do not build a records endpoint for a decoration. Live scores in the slip are the same story: the LIVE state is fine on graded data alone, showing PENDING until a result lands, and no polling. Everything else reads odds, mine, board, weeks, week, stats and seasons.
40 · No destructive controls
Deliberately absent: clear all, delete week, empty submit. Tapping a filled slot removes that one pick locally and the submit button disables itself — there is no path that posts fewer than five picks, and no path that changes a started game. Queries needs a real empty state too: name the view and the season and say no picks were graded there yet, not "Nothing to show".

27 · Ship the system font stack
These mocks are drawn in Barlow and JetBrains Mono. Webfonts are allowed but render-blocking on cellular, and the typeface is not doing real work here — the numbers just need to be monospaced so columns align. Top right of the header on all pages, since it governs every tab. When it isn't the newest season, give the control an amber outline and the page a one-line banner — otherwise people hunt for this week's missing games. Hall of Fame doesn't need it; it spans all seasons.

Rows sort by wins, so the amber tint marks first place and the trophy separately marks everyone equal to max(weeksWon) — in 5c that is the same person, but they can differ, and the design has to survive that. Desktop restores the columns the phone drops: weeks won, pushes, pending.

The backend replaces a week's picks until one grades, so 5a and 5b say that plainly and 5b offers Replace picks. If you'd rather it truly lock at submit, that's a backend change too — pick one behavior and make both sides agree.
31 · Queries matches fn=stats exactly
The eight VIEW options are the eight qView values, nothing invented: markets, units, leagues, weeks, cum, teamsW, teamsL, players. BUILD NOTES
13 · Three controls, eight views
VIEW is qView with the eight values the render code already switches on, labelled in plain words: Win % by player, Win % by market, Units by market, NFL vs college, Win % by week, Cumulative units, Best teams, Worst teams. PLAYER is qPlayer — All players or one of the nine. SEASON is the shared seasonPicker, since fn=stats has no week-range filter. The readout under the title prints the raw view name and season, so a screenshot in the group chat is self-explaining.
14 · Chart type follows the view
The two week views — Win % by week and Cumulative units — draw a line, because they are time. The other six are comparisons and draw bars: horizontal on the phone, where nine full names need the width, and vertical columns on desktop (see 4a and note 24). Sort direction is baked into the view rather than a control, which is why Best teams and Worst teams are separate options; the outermost bar is amber, the rest muted amber-grey.
15 · Win % starts at 30, not 0
Everyone lands between .450 and .600, so a 0-based axis flattens the whole league into one blob. Line charts clip the axis to 30–105% and mark 50% with a heavier dashed rule; bars stay proportional to the max value with the break-even marker called out. The unit views are the opposite case and need a signed baseline: zero sits mid-track, positives grow one way and negatives the other in red, all scaled off the largest absolute value. Never draw a negative by magnitude alone — the worst performer ends up with the tallest bar.
16 · Charts are SVG with a viewBox
width:100% plus a fixed viewBox means one chart scales from 390px to desktop with no redraw and no chart library. Axis text lives inside the SVG at ~15 viewBox units so it renders around 11px on the phone. Don't set a pixel width on the svg.
